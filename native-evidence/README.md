# A2-C0 native experiment

Disposable design prototype based on main c084560, not a C1 implementation. Captures are Windows Tauri 2 / WebView2 with the real CodeMirror editor and a disposable SQLite universe. Window size controls requested 800x600 and 1280x800 logical pixels. Windows capture images include a 1px outline on each side, so the files measure 802x602 and 1282x802. The selectors are experiment controls, not a proposed product toolbar. The earlier B 800 and close-guard captures have mojibake in experimental titlebar labels; a later rebuild corrected those labels. The native font captures and H/A captures use the corrected build. All prose is synthetic; the long document repeats three invented paragraphs 20 times.

A reserves the 230px library region at all widths. B reclaims it and recenters the editor when folded. H uses a 230px overlay at widths <=900px and otherwise behaves like A. At 800 the overlay covers the left side of the text temporarily; it can be dismissed with the same Menu button. It is a feasibility sketch, not an accessible or polished drawer implementation. It does not auto-dismiss on selection or Escape, and its focus behavior has not been validated. These are mandatory questions before implementation.

## Results

- A at 800 is narrow and off-center when the library is hidden. B makes text wider and changes wraps. See a-800-visible, a-800-hidden, b-800-visible and b-800-hidden.
- H at 800 keeps the text behind the drawer at the same location and provides a wide centered column when the drawer is shut. See h-800-visible and h-800-hidden. At 1280 it docks the sidebar and retains the reserved frame on folding, as in h-1280-visible and h-1280-hidden. Compare b-1280-hidden.
- In CodeMirror at 800 H, double-clicking the word `en` produced a visible selection. It remained visibly selected at the same location through opening and closing the overlay. See h-selection-before, h-selection-overlay and h-selection-after. This is a single short-document selection observation, not a comprehensive caret/IME/focus test. Focus is moved to the menu button; keyboard return to the editor and scroll anchoring with an active selection are unverified.
- The long real CodeMirror document scrolled in the native window. See long-scroll-1280. B's fold visibly shifts the scrolled column at 1280, though the same passage remained visible in this one observation. Empty state is in empty-1280.
- The custom X invoked a Rust command calling window.close(), which delivered the existing CloseRequested handler. With a synthetic body edit, X showed the actual dirty dialog; Continue editing kept the draft. Alt+F4 showed the same guard, then Discard closed that disposable draft. See custom-close-guard. This is a narrow observation, not an exhaustive safety or persistence certification. No unguarded destroy is added. Existing guarded Rust close_window still consumes the permit before destroy.
- Custom maximize expanded the window, and its button restored the 1280x800 window. Custom minimize made the target unavailable to the Windows automation API as minimized; restoring that minimized instance was not verified, and a second instance was launched for remaining observations. Programmatic setSize produced both captured sizes; manual edge resizing and min constraints were not verified. Titlebar drag, double-click, Windows Snap, full keyboard navigation, and OS close other than Alt+F4 are untested.
- The existing UI suite passed 64/64 before the final isolated CSS/HTML correction, and desktop TypeScript check passed. Build succeeded after that correction. An existing Rust warning about unused `point` remains. No full native data persistence or full Rust suite is claimed.

The selected font files come from the Google Fonts repositories and their OFL notices are alongside them. The native h-800-hidden, h-800-literata and h-800-source-sans images use the same short document and size. The font switch changes rendering, but computed-family/loading verification and emoji fallback identity were not measured in WebView2. The previous Edge comparison did verify Font Loading API checks. Font choice remains for Valen and Ari.

Recommendation to review: H at small widths and A when docked on larger windows offers a wide stable small-window surface, at the cost of temporarily obscured text and the need for a real accessible dismiss/focus policy. B is balanced when closed but changes position, and at 800 changes wraps. A is the simpler invariant-preserving alternative but leaves an unused left region. Do not treat this as approval to implement H; test its focus, caret, scroll, overlay dismissal, selection, and real guard behavior across representative cases before C1.
